# 조선미녀 + 아누아 실제 제품 추가

"더 늘려봐"에 따라, **자사몰에서 전성분 확보가 실패했던 두 브랜드**를 올리브영+KCIA
파이프라인으로 재시도했다. 두 브랜드 모두 자사몰 자체는 못 썼지만(조선미녀는 상세페이지가
전부 이미지, 아누아는 자사몰 HTML에 OCR 오타 다수), 올리브영에 입점해 있으므로 올리브영의
법정 "상품정보 제공고시"를 통해 정상적으로 뚫었다.

## 추가한 것

- **조선미녀 맑은쌀채운 토너 150ml**(올리브영 경유): 29개 성분 표기 → 30개 성분으로 파싱
  (양 끝 구분자 처리 후), KCIA로 전부 검증.
- **아누아 PDRN 히알루론산 100 수분 크림 60mL**(올리브영 경유): 45개 성분, KCIA로 44개
  검증 (아래 참고).

## 검증 중 잡은 것

- CosIng의 실제 등록 INCI 문자열은 관용명 괄호를 안 붙이는 경우가 있다. 처음엔 "Oryza
  Sativa (Rice) Extract"·"Ficus Carica (Fig) Fruit Extract"·"Theobroma Cacao (Cocoa) Seed
  Extract"·"Solanum Melongena (Eggplant) Fruit Extract"·"Curcuma Longa (Turmeric) Root
  Extract"로 넣었더니 5개가 매칭 실패 → `ingredient_ref.cosing_ingredients`를 직접
  조회해서 실제 등록명("Oryza Sativa Extract" 등, 괄호 없음)을 확인하고 정정. 짐작으로
  고치지 않고 레퍼런스 데이터를 직접 확인했다.
- "C12-13알케스-9"(아누아 크림)는 CosIng에 아예 없는 성분이다. 이름이 비슷한 "C12-13
  Pareth-9"(다른 에톡실화 계열, 별개 물질)로 대충 매칭시키지 않고, **의도적으로 미매칭
  처리**했다 — 44/45로 남김. 성분표 원문은 그대로 보존, DB 연결만 스킵.

## 실사용 검증

- 테스트 유저로 로그인 → `skin_profiles`에 `goals=['hydration','wrinkle_elasticity']`로
  체크인 삽입 → `/recommendations`에서 실제 확인:
  - 조선미녀 토너: "목표(수분·보습)에 맞는 글리세린 함유" + 향/제형/무착색 선호 일치 문구
    정상 노출, 실제 썸네일 렌더링 확인.
  - 아누아 크림: "목표(수분·보습)에 맞는 스쿠알란 함유" + **"목표(주름·탄력)에 맞는
    아데노신 함유"**까지 정확히 노출 — 아데노신이 `wrinkle_elasticity` 목표와 연결되는
    걸 실제 추천 결과로 확인했다.
  - EU Annex II 금지성분 없음, `country='KR'` 정상 태그 확인(SQL).
- 테스트 유저 삭제로 정리 완료.

## 지금까지 실제 제품 총계

COSRX 7개 + Round Lab 5개 + 올리브영(구달 1, 넘버즈인 1, 조선미녀 1, 아누아 1) + iHerb
(ISNtree 1) = **17개 실제 제품**, 7개 브랜드, 4개 경로(브랜드 공식몰 2곳 + 한국 종합몰
1곳 + 해외 리셀러 1곳). DB 전체 `country='KR'` 12개, 전체 상품 28개(테스트 더미 포함).

## 여전히 유효한 제약

`0016_...md`/`0017_...md`에 적은 대로, 올리브영·KCIA 둘 다 서버사이드 요청으로는 막혀
있어 이 대화의 브라우저 세션으로만 동작한다. 자동 대량 수집은 헤드리스 브라우저 인프라가
필요한 별도 아키텍처 결정 사항.
